# ComfortLine: Replit to Cloudflare Workers migration

This file documents the staging migration only. Do not delete DNS records, disconnect Replit, or cancel Replit until the new Worker has passed all checks.

## Repository

- Source: https://github.com/rakuci/Comfort-Line-Rebrand
- Branch: cloudflare-migration (do not deploy main as the Cloudflare app until merged)
- Worker name: comfortline (separate from the existing bycomfortline Worker)
- Config: wrangler.jsonc at the repository root
- API: cloudflare/worker.mjs
- Static assets: artifacts/comfortline-website/dist/public (generated by prerender)
- Page URLs use drop-trailing-slash to preserve previous canonical URLs.
- Unknown routes return HTTP 404 rather than a soft-404 SPA homepage.

## Initial Cloudflare Git build settings

In Cloudflare → Workers & Pages → Create application → GitHub:

1. Select rakuci/Comfort-Line-Rebrand.
2. Name the Worker comfortline.
3. Set the production branch to cloudflare-migration.
4. Set root directory to the repository root (/; not artifacts/comfortline-website).
5. Set build command to:
   npm install --global pnpm@10 && pnpm install --frozen-lockfile && pnpm --filter @workspace/comfortline-website build && node --test cloudflare/worker.test.mjs
6. Set deploy command to:
   npx --yes wrangler@4 deploy
7. Deploy first to the Cloudflare-provided workers.dev address. Do not attach comfortline.by yet.
8. If the build fails, review the log and fix the migration branch; do not fall back to the unrelated bycomfortline Worker.

Build logs may be lengthy because the existing site prerenders localized pages and generates Open Graph images. The build should complete with no missing dependencies or failed tests.

## Runtime secrets (Worker settings → Variables and Secrets)

Add to the comfortline Worker, never to source files or Cloudflare build variables:

- RESEND_API_KEY: required for POST /api/booking and POST /api/contact.
- INSTAGRAM_ACCESS_TOKEN: optional, required if the Instagram widget is in use.

Outgoing email is ComfortLine <noreply@comfortline.by> to info@comfortline.by. Confirm the domain is verified for sending in the same Resend account as the token.

The border queue API does not use a secret but it depends on an external Jina reader service. Test it separately and display stale/unavailable states properly if the upstream cannot be reached.

## Worker smoke checks

Using the Cloudflare temporary URL (use the actual address provided):

- / — homepage HTML, HTTP 200
- /en — English landing page, HTTP 200
- /blog and /блог — localized blog pages, HTTP 200
- Representative airport/transfer pages — content, images, correct canonical tags, HTTP 200
- /sitemap.xml, /robots.txt, favicon, images — HTTP 200
- /api/healthz — JSON status ok
- /api/border-queue — JSON status, check external source behavior
- /api/instagram/posts — JSON posts, configured fields
- /this-page-does-not-exist-migration-test — HTTP 404, X-Robots-Tag noindex
- POST /api/contact — real test email with separate confirmation in Resend and Yandex inbox
- POST /api/booking — real test booking; verify inbox and UI success/error state
- Verify mobile layout, language switching, internal links, page titles, metadata and structured data.
- Verify no new pages redirect to Replit and no replit.app runtime dependencies.

Workers API enforces basic length and required-field checks and escapes HTML in email templates. For production public forms, consider Turnstile and rate limiting after core migration is verified.

## Cutover — only after all tests pass

1. Save a backup of Cloudflare DNS (15 records as last observed).
2. In Cloudflare Workers → comfortline → Settings → Domains & Routes, add custom domain comfortline.by. Cloudflare may ask to update/replace the conflicting proxied CNAME for the root. Do this only during cutover.
3. Configure www.comfortline.by to redirect to https://comfortline.by (or attach it with a deliberate redirect). Replace the old www CNAME only as required.
4. Keep unchanged: Yandex MX and mail CNAME, SPF, DKIM, DMARC, Amazon/SES and Resend sending-domain records, search verification TXT.
5. Check HTTPS, forms, SEO tags, sitemap, page-level redirects, Google Search Console, and Yandex Webmaster after the move. Trigger IndexNow separately when production is confirmed (build script only submits automatically on Replit deploys or with INDEXNOW_SUBMIT=1).
6. Unpublish the Replit deployment when the new hostname has been verified.
7. Cancel any paid Replit subscription separately in Replit billing, only after confirming no other Replit projects require it.

## Notes

- This is a parallel Worker implementation of the existing Express endpoints. The legacy Express backend remains unchanged in the Replit project for rollback.
- Cloudflare's per-isolate in-memory API caches are best-effort and not global. The border-queue service can be unavailable independently of the hosting migration.
- Worker and build changes on cloudflare-migration do not change the current comfortline.by DNS.
